02 / 資料清理

保留可追溯的來源，
排除不適合抽選的記錄。

  • 合併原有 16 筆及新一批 2,755 筆資料，按來源識別碼合併 2 筆重複；不按同名合併分店。
  • 排除 42 筆境外資料，以及 62 筆非餐廳／類型不明記錄。
  • 匯入 2,665 間；277 間未分類、15 間明確停業，不進入抽選，兩者有重疊。最後可抽選 2,376 間。
  • 菜式只按經整理的來源分類對照；不按店名或搜尋字眼猜測。保留名稱、地址、座標、來源評分、Google Maps 餐廳連結、分類及更新日期。
  • 不打包文字評論、評論者資料、電話或電郵。評分與資料日期是匯入快照，並非即時驗證。

資料來自 gosom 匯出與本機整理。工具開源不等於來源資料的再發布授權；正式發布前仍須確認相關資料使用條款。行政區邊界資料來源：香港特別行政區政府民政事務總署。

03 / 維護者工作流程

匯出、整理、驗證，再打包。

  1. 在電腦執行 gosom

    Windows 可透過 Docker Desktop 的 Linux containers 執行，毋須更換作業系統。依 gosom 官方說明 匯出 JSON／JSONL，不收集額外文字評論。原始檔放在忽略 Git 的 gosom-data/。

  2. 更新確認菜式對照及檢查資料

    菜式對照在 tools/gosom-cuisine-map.json。沒有對照的餐廳保持未分類。明確 CLOSED 等狀態才視為停業；描述文字及空白狀態保持未知。

  3. 合併及產生內置清單
    python tools/review_gosom_catalog.py gosom-data/results.json gosom-data/results-hk-20261103.json --date 2026-11-03 --sync-localities

    由專案根目錄執行，日期換成實際整理日期。輸入檔由舊至新排列，相同來源識別碼採後一快照；執行前保留原始檔。輸出 app/src/main/assets/restaurants.json，同時更新地點顯示分組；完整排除清單在 gosom-data/import-report.json。上述原始輸入檔不在 GitHub，須由維護者自行提供。

  4. 執行檢查，再重新建置
    python -m unittest discover -s tools -p 'test_*catalog.py' -v
python -m unittest discover -s tools -p test_district_boundaries.py -v

    以 Android Studio 建置 demoDebug 或 liveDebug；兩者目前均使用本機資料，debug 廣告使用官方測試單元。tools/verify-community.ps1 保留建置及測試流程。選與手機既有安裝相同的版本更新，資料才會生效。

不需要 Supabase 專案或長期開機的私人電腦。更新邊界時，從官方來源另行下載並核對版本，重新測試及產生資料；App 不會在執行時下載行政區邊界。

04 / 目前驗證狀態

已驗證的，與尚待確認的。

已完成

選單收合更新已通過 demoDebug／liveDebug 建置、36 項單元測試和 8 項模擬器篩選測試。測試涵蓋選單展開及收起、保留選擇，以及定位與地區互斥。動畫整合階段另有 31 項資料及匯入測試通過。較早的 AGP 9.5.0 建置曾通過 Android lint，另有 175 項警告。0.3.1 兩個 APK 已確認包含 16 張逐格動畫圖集及 2,665 間餐廳；保留原本靜態角色作停用動畫時的回退。

仍有範圍限制

0.3.1 的 9 項畫面／定位取消競態測試通過；動畫整合亦完成逐格、靜態回退、抽選重抽及日夜模式驗證。首次原生定位提示測試受模擬器 System UI 無回應阻擋，實體手機定位及全面回歸仍待確認。
