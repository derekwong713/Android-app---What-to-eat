01 / 使用方法

兩次抽選，一個去處。

  1. 設定距離及菜式

    想用距離篩選時才取得目前位置；不提供定位亦可選擇不限距離。距離是直線距離，不是步行距離。

  2. 抽菜式，再抽餐廳

    從符合條件的候選內，等機率抽取不同菜式，再於該菜式中等機率抽一間店。廣告及評分不影響機率。

  3. 重抽，或者出發

    「重抽餐廳」保留菜式；「重抽菜式」重新執行兩個階段。「導航」會開啟外部 Google Maps。

多個候選時避免立即重複；只有一個時會提示。零候選不會自動放寬條件。多菜式餐廳在同一菜式的候選中只計一次。

02 / 本機資料

資料跟住 App，
抽選留喺手機。

App 讀取內置餐廳清單，不需要 Supabase 或登入帳戶。餐廳篩選及抽選可在本機執行；定位、廣告及外部導航則各有裝置或網絡要求。

保留甚麼？
名稱、地址、座標、確認菜式、評分及評分數量、來源和更新日期。
不提供甚麼？
註冊、用戶評分提交、文字評論及社群修改入口。
怎樣更新？
重新整理資料並發布新版 App。內置評分不是即時評分；請留意詳情中的資料日期。
沒有分類／評分？
不憑店名猜測菜式；未分類餐廳不參與菜式抽選。缺少評分顯示「暫無評分」。

03 / 維護者指南

從匯出檔到內置清單。

在 Windows 電腦使用 Docker Desktop 執行 gosom，匯出 JSON 或 JSONL。毋須在用家的手機執行爬蟲，亦毋須讓私人電腦長期開機。

  1. 小批量匯出

    依 gosom 官方文件建立搜尋清單，使用 -json 輸出。無須額外收集文字評論；搜尋結果不等於完整餐廳名錄。

  2. 確認菜式及營業狀態

    為每筆資料整理 confirmed_cuisines。檢查已停業店舖、座標及重複結果；目前整理工具不會自動映射營業狀態。

  3. 產生 App 資料
    python tools/prepare_bundled_catalog.py export.json --date 2026-11-02

    在專案根目錄執行，日期換成實際資料日期。輸出至 app/src/main/assets/restaurants.json。整理工具按來源識別碼去重，捨棄評論內容。

  4. 驗證及重新建置

    確認非空、可分類及座標有效，再使用 Android Studio 建置、測試及安裝。現時 Android 編譯仍受環境的 loopback connection 錯誤阻擋，不能把舊版測試結果當作本版驗證。

開源工具的程式授權不等於來源資料的再發布授權；打包及發布前須確認相關資料使用條款。

04 / 常見問題

開始前，你可能想知。

要轉用 Linux 嗎？

不用。Windows 可透過 Docker Desktop 的 WSL 2 環境執行 Linux containers，繼續使用 Windows 及 PowerShell。

為甚麼現在抽不到餐廳？

專案的內置清單尚未有真實餐廳。需要先匯入、確認菜式並重新建置 App；單純放入原始匯出檔不會自動完成分類。

Google 評分會自動更新嗎？

不會。評分是匯入時的快照，只有更換內置資料並更新 App 才會更新。

定位及私隱如何處理？

距離篩選使用裝置目前位置，本機版本不把位置送到 Supabase。廣告仍使用 AdMob 及適用的同意流程，外部 Google Maps 有其自身私隱政策。正式發布前仍需完善營運者、聯絡資料及私隱政策。
